Preprocesamiento

TipResumen en 30 segundos

El preprocesamiento transforma los datos originales en una representación adecuada para el análisis y el modelado.

Incluye decisiones sobre:

  • Separación de datos.
  • Valores ausentes.
  • Escalado.
  • Variables categóricas.
  • Outliers.
  • Pipelines.
  • Prevención de data leakage.

Un buen modelo no compensa un preprocesamiento incorrecto.

Objetivo de esta sección

Esta sección reúne los pasos necesarios para preparar los datos antes de entrenar un modelo de machine learning.

El objetivo no es aplicar transformaciones automáticamente, sino construir un flujo:

  • Reproducible.
  • Justificado.
  • Clínicamente coherente.
  • Libre de data leakage.
  • Compatible con validación cruzada.
  • Fácil de reutilizar en nuevos proyectos.

Orden recomendado

Un flujo habitual puede seguir este orden:

  1. Definir la unidad de análisis.
  2. Definir la variable objetivo.
  3. Definir el momento de predicción.
  4. Separar train, validation y test.
  5. Revisar data leakage.
  6. Analizar valores ausentes.
  7. Revisar outliers y unidades.
  8. Preparar variables numéricas.
  9. Preparar variables categóricas.
  10. Integrar todo en un pipeline.
  11. Validar el flujo completo.
  12. Evaluar finalmente con test.
NoteIdea clave

El orden de las transformaciones importa.

Muchas operaciones deben aprenderse únicamente con el conjunto de entrenamiento.

Qué debe hacerse antes del pipeline

Normalmente, antes del pipeline se realizan decisiones estructurales:

  • Definir la cohorte.
  • Crear la variable objetivo.
  • Definir el momento de predicción.
  • Armonizar unidades.
  • Corregir errores conocidos.
  • Excluir variables con leakage.
  • Separar por paciente, tiempo o centro.
  • Eliminar identificadores de las variables predictoras.

Qué debe estar dentro del pipeline

Normalmente, dentro del pipeline se incluyen:

  • Imputación.
  • Escalado.
  • Encoding.
  • Selección de variables.
  • PCA.
  • Balanceo.
  • Modelo.
WarningImportante

Si una transformación aprende parámetros a partir de los datos, debería formar parte del pipeline o ajustarse únicamente con train.

Ejemplo conceptual

model = Pipeline(
    steps=[
        (
            "preprocessor",
            preprocessor
        ),
        (
            "classifier",
            LogisticRegression(
                max_iter=1000,
                random_state=42
            )
        )
    ]
)

Errores frecuentes

  • Preprocesar antes del split.
  • Imputar con todo el dataset.
  • Escalar train y test por separado.
  • Mezclar pacientes entre particiones.
  • Utilizar información futura.
  • Tratar códigos categóricos como cantidades.
  • Eliminar outliers automáticamente.
  • No armonizar unidades.
  • Comparar modelos con splits diferentes.
  • Guardar solo el modelo y no el pipeline.

Consideraciones en datos clínicos

NoteAplicación clínica

El preprocesamiento no es solo una tarea técnica.

Cada decisión puede modificar:

  • La población analizada.
  • La representación de los pacientes.
  • La interpretabilidad.
  • La validez externa.
  • La utilidad clínica del modelo.

Unidad de análisis

Puede ser:

  • Paciente.
  • Visita.
  • Ingreso.
  • Episodio.
  • Prueba.
  • Ventana temporal.

Debe quedar definida antes del split.

Tiempo índice

Es el momento exacto en que se genera la predicción.

Todas las variables predictoras deben estar disponibles antes o en ese momento.

Diferencias entre centros

Pueden existir diferencias en:

  • Protocolos.
  • Equipos.
  • Unidades.
  • Frecuencia de medición.
  • Sistemas de información.
  • Población atendida.

Datos longitudinales

Debe evitarse utilizar observaciones futuras para construir variables pasadas.
