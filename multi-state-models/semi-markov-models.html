Modelos semi-Markov

TipResumen en 30 segundos

Un modelo semi-Markov permite que el riesgo de la siguiente transición dependa del tiempo que el paciente lleva en el estado actual.

A diferencia de un modelo Markov puro:

Markov
→ importa el estado actual

Semi-Markov
→ importa el estado actual
  y cuánto tiempo lleva en él

Esto resulta útil cuando la duración en un estado modifica el riesgo de progresión, recuperación o salida.

¿Por qué semi-Markov?

En muchos procesos clínicos, dos pacientes en el mismo estado no tienen el mismo riesgo futuro si llevan tiempos muy distintos en él.

Ejemplo:

Paciente A
→ acaba de entrar en S1

Paciente B
→ lleva 12 meses en S1

Un modelo Markov puro puede tratarlos igual.

Un modelo semi-Markov permite tratarlos de forma distinta.

NoteIdea clave

El reloj relevante se reinicia al entrar en cada estado.

Propiedad semi-Markov

La siguiente transición puede depender de:

  • Estado actual.
  • Tiempo desde entrada en el estado.
  • Covariables.
  • Tiempo global, si se incluye.
  • Historia resumida.

Sojourn time

El tiempo de permanencia en un estado se denomina:

sojourn time

Si un paciente entra en S1 en el día 90 y sale en el día 180:

sojourn time
→ 90 días

Clock-reset

En un modelo semi-Markov se utiliza habitualmente:

clock-reset

El tiempo se mide desde la entrada en el estado actual.

Clock-forward frente a clock-reset

Clock-forward

Tiempo desde el origen global

Clock-reset

Tiempo desde la entrada en el estado

Ejemplo

Inicio tratamiento
→ día 0

Entrada en S1
→ día 100

Salida de S1
→ día 160

Clock-forward:

start = 100
stop = 160

Clock-reset:

start = 0
stop = 60

Intensidad semi-Markov

Para una transición (r s):

\[ q_{rs}(u) \]

donde (u) es el tiempo desde entrada en el estado (r).

Con covariables

\[ q_{rs}(u\mid X) = q_{rs,0}(u) \exp( \beta_{rs}^{\top}X ) \]

Interpretación

El baseline hazard puede variar con la duración en el estado.

Ejemplo:

S1 → S2
→ riesgo alto durante los primeros 3 meses
→ riesgo menor después

Diferencia frente a Markov no homogéneo

Markov no homogéneo

La intensidad depende del tiempo global:

q_rs(t)

Semi-Markov

La intensidad depende del tiempo desde entrada:

q_rs(u)

Ejemplo clínico

El riesgo de progresión de S1 a S2 puede depender de:

  • Tiempo desde inicio del tratamiento.
  • Tiempo desde entrada en S1.

Estas dos escalas no son equivalentes.

Preparar episodios de estado

Partimos de observaciones:

patient_id | time | state

Detectar entrada en nuevo estado

state_df = (
    state_df
    .sort_values(
        [
            "patient_id",
            "time"
        ]
    )
    .reset_index(
        drop=True
    )
)
state_df[
    "previous_state"
] = (
    state_df
    .groupby("patient_id")[
        "state"
    ]
    .shift()
)
state_df[
    "new_episode"
] = (
    state_df[
        "state"
    ]
    !=
    state_df[
        "previous_state"
    ]
).astype(int)

Para la primera observación:

state_df.loc[
    state_df[
        "previous_state"
    ]
    .isna(),
    "new_episode"
] = 1

Identificador de episodio

state_df[
    "episode_id"
] = (
    state_df
    .groupby("patient_id")[
        "new_episode"
    ]
    .cumsum()
)

Tiempo de entrada en estado

entry_times = (
    state_df
    .groupby(
        [
            "patient_id",
            "episode_id"
        ]
    )[
        "time"
    ]
    .min()
    .rename(
        "state_entry_time"
    )
    .reset_index()
)

Añadir entrada

state_df = state_df.merge(
    entry_times,
    on=[
        "patient_id",
        "episode_id"
    ],
    how="left"
)

Tiempo desde entrada

state_df[
    "time_since_state_entry"
] = (
    state_df[
        "time"
    ]
    -
    state_df[
        "state_entry_time"
    ]
)

Construir intervalos clock-reset

Partimos de intervalos globales:

patient_id | from_state | to_state | start | stop | status

Entrada al episodio

interval_data = interval_data.merge(
    episode_entry_table,
    on=[
        "patient_id",
        "episode_id"
    ],
    how="left"
)

Tiempo reset

interval_data[
    "reset_start"
] = (
    interval_data[
        "start"
    ]
    -
    interval_data[
        "state_entry_time"
    ]
)
interval_data[
    "reset_stop"
] = (
    interval_data[
        "stop"
    ]
    -
    interval_data[
        "state_entry_time"
    ]
)

Resultado

patient_id | from | to | reset_start | reset_stop | status
----------------------------------------------------------------
1          | S1   | S1 | 0           | 30         | 0
1          | S1   | S2 | 30          | 90         | 1

Riesgo en clock-reset

Para una transición desde S1:

reset_start
reset_stop

representan tiempo en S1, no tiempo desde el origen global.

Cox clock-reset

from lifelines import CoxPHFitter

transition_model = CoxPHFitter()
transition_model.fit(
    transition_df[
        [
            "reset_start",
            "reset_stop",
            "event",
            "age",
            "baseline_lvef",
            "cumulative_dose"
        ]
    ],
    duration_col="reset_stop",
    event_col="event",
    entry_col="reset_start"
)

Interpretación

El baseline hazard se interpreta en función del tiempo desde entrada en el estado.

Cause-specific por transición

Para S1:

S1 → S0
S1 → S2

Dataset expandido

Riesgos competidores dentro del estado

Cuando ocurre S1 → S0, se deja de estar en riesgo de S1 → S2 en ese episodio.

Reentrada en un estado

Un paciente puede:

S0 → S1 → S0 → S1

Cada entrada en S1 crea un nuevo episodio.

Episodios repetidos

S1 episodio 1
S1 episodio 2

Pueden tener:

  • Riesgo diferente.
  • Historia diferente.
  • Duración diferente.
  • Tratamiento diferente.

Dependencia entre episodios

Los episodios del mismo paciente no son independientes.

Puede ser necesario:

  • Error robusto por paciente.
  • Frailty.
  • Efectos aleatorios.
  • Modelo de recurrencia.

Tiempo en estado como covariable

Otra aproximación es incluir explícitamente la duración.

expanded_data[
    "time_in_state_at_start"

    expanded_data[
        "reset_start"

No linealidad

El efecto de la duración puede no ser lineal.

model.fit(
    transition_df,
    duration_col="reset_stop",
    event_col="event",
    entry_col="reset_start",
    formula=(
        "bs(time_in_state_at_start, df=4)"
        " + age"
        " + cumulative_dose"
    )
)

Atención

Si el baseline ya está definido sobre clock-reset, añadir tiempo en estado como covariable puede ser redundante o cambiar la interpretación.

Debe decidirse qué parte se modela en el baseline y cuál como covariable.

Parametric semi-Markov

Puede especificarse una distribución para el tiempo de salida del estado.

Ejemplos:

  • Weibull.
  • Log-normal.
  • Log-logístico.
  • Piecewise exponential.

Weibull por transición

from lifelines import WeibullAFTFitter

weibull_transition = WeibullAFTFitter()
weibull_transition.fit(
    transition_df[
        [
            "sojourn_time",
            "event",
            "age",
            "cumulative_dose"
        ]
    ],
    duration_col="sojourn_time",
    event_col="event"
)

Interpretación AFT

El modelo describe cómo las covariables aceleran o retrasan la salida del estado.

Ejemplo

TR = 0.75

puede indicar un tiempo hasta salida aproximadamente un 25 % menor.

Salida hacia varios destinos

Si un estado tiene varias salidas, puede modelarse:

  • Cause-specific AFT.
  • Competing risks paramétrico.
  • Distribución conjunta de tiempo y destino.
  • Modelos multiestado especializados.

Piecewise exponential

Puede permitir una intensidad distinta según duración.

>90 días

Kaplan-Meier de permanencia

Puede estimarse el tiempo hasta salida de un estado.

Ejemplo para S1

from lifelines import KaplanMeierFitter

s1_episodes = episode_df.loc[
    episode_df[
        "state"
    ]
    ==
    "S1"
]
kmf = KaplanMeierFitter()

kmf.fit(
    durations=s1_episodes[
        "sojourn_time"
    ],
    event_observed=s1_episodes[
        "left_state"
    ],
    label="Permanencia en S1"
)

Limitación

Si existen varios destinos, las salidas son competing risks.

Kaplan-Meier de salida total estudia:

Tiempo hasta abandonar S1

no el destino específico.

CIF por destino

Desde S1:

S1 → S0
S1 → S2

pueden estimarse incidencias acumuladas específicas por tiempo en estado.

Comparar Markov y semi-Markov

Aspecto Markov Semi-Markov
Memoria Estado actual Estado + duración
Reloj Global Reinicia por estado
Sojourn time Exponencial en homogéneo Flexible
Complejidad Menor Mayor
Interpretación Simple Más clínica si importa duración

Predicción semi-Markov

La predicción necesita conocer:

  • Estado actual.
  • Tiempo ya pasado en el estado.
  • Covariables actuales.
  • Historia relevante.

Ejemplo

Paciente en S1
desde hace 60 días

La predicción no debe reiniciarse como si acabara de entrar.

Residual life

Interesa:

Tiempo adicional esperado
antes de salir del estado

condicionado a haber permanecido ya (u) unidades.

Supervivencia residual

\[ P( T > u + v \mid T > u ) = \frac{ S(u+v) }{ S(u) } \]

Ejemplo en Python

survival_u = model.predict(
    u
)

survival_u_plus_v = model.predict(
    u
    +
    v
)

residual_survival = (
    survival_u_plus_v
    /
    survival_u
)

Ocupación semi-Markov

Calcular probabilidades de ocupación puede requerir:

No siempre puede obtenerse con una única exponencial matricial.

Simulación

Una estrategia práctica es simular:

  1. Tiempo hasta salida.
  2. Destino.
  3. Nueva entrada.
  4. Repetir hasta horizonte.

Simulación conceptual

def simulate_sojourn_time(
    state,
    patient,
    rng
):

    if state == "S1":

        shape = 1.5
        scale = 60

        return rng.weibull(
            shape
        ) * scale

    return rng.exponential(
        90
    )

Elegir destino

def choose_destination(
    state,
    rng
):

    if state == "S1":

        return rng.choice(
            [
                "S0",
                "S2"
            ],
            p=[
                0.55,
                0.45
            ]
        )

    return state

con reloj reiniciado al entrar en cada estado.

El tiempo hasta la siguiente transición
se modeló desde el inicio del episodio,
permitiendo que la intensidad dependiera
de la duración en el estado.

Errores frecuentes

  • Llamar semi-Markov a un modelo clock-forward.
  • No reiniciar el reloj.
  • Mezclar episodios.
  • No identificar reentradas.
  • Asumir independencia entre episodios.
  • Usar tiempo total en estado futuro.
  • Ignorar salidas competidoras.
  • No considerar incertidumbre de fechas.
  • Comparar AIC de estructuras distintas sin cuidado.
  • No validar sojourn times.
  • Crear demasiados subestados.
  • No declarar la escala temporal.

Flujo recomendado

  1. Identificar episodios.
  2. Definir entrada en estado.
  3. Calcular clock-reset.
  4. Construir intervalos.
  5. Definir destinos competidores.
  6. Ajustar modelos por transición.
  7. Modelar duración.
  8. Incluir covariables.
  9. Revisar episodios repetidos.
  10. Estimar predicciones.
  11. Validar.
  12. Comparar con Markov.
