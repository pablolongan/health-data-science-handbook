Series temporales

TipResumen en 30 segundos

Una serie temporal es una secuencia de observaciones ordenadas en el tiempo.

El orden importa.

En estos problemas no debe mezclarse información futura con el pasado.

Los objetivos principales son:

  • Describir evolución.
  • Detectar patrones.
  • Predecir valores futuros.
  • Detectar cambios.
  • Identificar anomalías temporales.

¿Qué es una serie temporal?

Una serie temporal contiene observaciones registradas a lo largo del tiempo.

Ejemplos:

  • Frecuencia cardiaca cada minuto.
  • Presión arterial cada hora.
  • Ingresos hospitalarios por día.
  • Biomarcadores por visita.
  • Ocupación de camas por semana.
  • Ventas mensuales.
  • Temperatura de un sensor.
Tiempo
──────────────────────────────→

y₁  y₂  y₃  y₄  y₅  ...  yₜ
NoteIdea clave

En series temporales, el orden de las observaciones forma parte de los datos.

Diferencia con datos tabulares

En datos tabulares suele asumirse que las filas son intercambiables.

En series temporales:

Pasado
→ presente
→ futuro

Cambiar el orden destruye información.

Tipos de problemas

Forecasting

Predecir valores futuros.

Ejemplos:

  • Ocupación de camas mañana.
  • Duración de estancia restante.
  • Biomarcador en la siguiente visita.
  • Demanda asistencial la próxima semana.

Clasificación temporal

Predecir una categoría a partir de una secuencia.

Ejemplos:

  • Deterioro en las próximas 6 horas.
  • Arritmia: sí o no.
  • Reingreso en 30 días.
  • Cambio de estado clínico.

Detección de anomalías

Identificar patrones temporales inusuales.

Ejemplos:

  • Cambio brusco de sensor.
  • Deterioro inesperado.
  • Error de registro.
  • Ruptura de tendencia.

Imputación temporal

Estimar valores ausentes aprovechando observaciones anteriores y posteriores.

Segmentación

Dividir una serie en periodos con comportamiento diferente.

Componentes de una serie temporal

Una serie puede contener:

  • Nivel.
  • Tendencia.
  • Estacionalidad.
  • Ciclos.
  • Ruido.
  • Cambios estructurales.

Nivel

Es el valor medio alrededor del cual fluctúa la serie.

Tendencia

Es un cambio sostenido a largo plazo.

Valores
   │
   │        /
   │      /
   │    /
   │  /
   └──────────── Tiempo

Estacionalidad

Es un patrón que se repite con frecuencia conocida.

Ejemplos:

  • Ciclo diario.
  • Ciclo semanal.
  • Ciclo anual.
  • Mayor actividad en días laborables.

Ciclo

Es una oscilación de duración variable, no necesariamente fija.

Ruido

Variación no explicada por los componentes anteriores.

Frecuencia temporal

Debe identificarse la frecuencia de observación.

Ejemplos:

1 minuto
1 hora
1 día
1 semana
1 visita

Una serie puede ser:

  • Regular.
  • Irregular.

Serie regular

Las observaciones están separadas por intervalos constantes.

08:00
09:00
10:00
11:00

Serie irregular

Los intervalos son variables.

Día 0
Día 7
Día 23
Día 90

Esto es frecuente en datos clínicos longitudinales.

Lags

Un lag representa un valor pasado.

df["value_lag_1"] = (

Varios lags

df[

Evitar leakage en rolling features

Para predecir el tiempo (t), la ventana debe contener solo información anterior.

df[
    "rolling_mean_7"
] = (
    df["value"]
    .shift(1)
    .rolling(
        window=7
    )
    .mean()
)
ImportantRegla práctica

Aplica shift(1) antes de calcular estadísticas si no debe incluirse el valor actual.

Horizonte de predicción

Debe definirse cuánto futuro se quiere predecir.

Ejemplos:

1 hora
6 horas
24 horas
7 días
30 días
1 visita

Forecast horizon

Tiempo de predicción
        │
        ├── t + 1
        ├── t + 2
        └── t + H

Predicción one-step

Predice el siguiente instante.

Predicción multi-step

Predice varios pasos futuros.

Estrategia recursiva

Utiliza predicciones anteriores para predecir pasos posteriores.

Predice t+1
→ usa predicción para t+2
→ usa predicciones para t+3

Puede acumular error.

Estrategia directa

Entrena un modelo distinto para cada horizonte.

Modelo 1 → t+1
Modelo 2 → t+2
Modelo 3 → t+3

Estrategia multi-output

Un único modelo predice varios horizontes.

Gap temporal

El gap evita que observaciones muy próximas aparezcan en train y validation.

Métricas de forecasting

  • MAE.
  • RMSE.
  • MAPE.
  • sMAPE.
  • MASE.
  • WAPE.

MAE

from sklearn.metrics import mean_absolute_error

mae = mean_absolute_error(
    y_test,
    y_pred
)

RMSE

from sklearn.metrics import root_mean_squared_error

rmse = root_mean_squared_error(
    y_test,
    y_pred
)

MAPE

\[ MAPE = \frac{100}{n} \sum \left| \frac{ y_t-\hat{y}_t }{ y_t } \right| \]

Problemas:

  • No funciona bien con ceros.
  • Puede explotar con valores pequeños.
  • Es asimétrica.

sMAPE

Utiliza una escala simétrica aproximada.

También puede ser inestable cerca de cero.

MASE

Compara el error con un baseline naive.

MASE < 1
→ mejor que naive

MASE > 1
→ peor que naive

Evaluación por horizonte

No debe reportarse solo una métrica global.

Horizonte 1 día
Horizonte 3 días
Horizonte 7 días

El error suele aumentar con el horizonte.

Intervalos de predicción

Una predicción útil debería incluir incertidumbre.

Predicción central
+
límite inferior
+
límite superior

Cobertura

Un intervalo del 95 % debería contener aproximadamente el 95 % de observaciones futuras, bajo las condiciones del modelo.

Descomposición

Una serie puede descomponerse en:

\[ y_t = T_t + S_t + R_t \]

donde:

  • (T_t): tendencia.
  • (S_t): estacionalidad.
  • (R_t): residuo.

STL

from statsmodels.tsa.seasonal import STL

decomposition = STL(
    daily_series,
    period=7
).fit()
decomposition.plot()

plt.show()

Estacionariedad

Una serie estacionaria mantiene aproximadamente:

  • Media constante.
  • Varianza constante.
  • Dependencia temporal estable.

Muchos modelos clásicos requieren estacionariedad.

Pipeline temporal

from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.ensemble import HistGradientBoostingRegressor

model = Pipeline(
    steps=[
        (
            "imputer",
            SimpleImputer(
                strategy="median"
            )
        ),
        (
            "regressor",
            HistGradientBoostingRegressor(
                learning_rate=0.05,
                max_iter=300,
                random_state=42
            )
        )
    ]
)

Series por paciente

En datos clínicos puede haber múltiples series.

Paciente 2

Debe decidirse si el modelo es:

  • Individual.
  • Global.

Modelo global

Entrena con múltiples series y añade identificadores o características estáticas.

Ventajas:

  • Más datos.
  • Aprende patrones compartidos.
  • Puede generalizar a pacientes nuevos.

Irregularidad clínica

Opciones:

Censura

En salud puede ocurrir que:

  • El seguimiento termine.
  • El evento no ocurra.
  • El paciente abandone.
  • La observación se interrumpa.

En estos casos puede ser más adecuado:

  • Survival analysis.
  • Time-to-event.
  • Modelos multiestado.
  • Joint longitudinal-survival models.

Leakage temporal

Ejemplos frecuentes:

  • Usar el valor futuro para imputar.
  • Calcular rolling mean con el punto actual.
  • Normalizar con todo el periodo.
  • Seleccionar variables usando test.
  • Crear target con información posterior mal alineada.
  • Mezclar episodios del mismo paciente.
CautionPrecaución

El leakage temporal puede producir resultados artificialmente excelentes.

Drift temporal

Con el tiempo cambian:

  • Protocolos.
  • Equipos.
  • Población.
  • Tratamientos.
  • Codificación.
  • Prevalencia.
  • Estacionalidad.

Debe monitorizarse:

  • Error por periodo.
  • Distribución de features.
  • Calibración.
  • Frecuencia de alertas.
  • Residuos.

Backtesting

Backtesting simula cómo habría funcionado el modelo en distintos momentos históricos.

Entrenar hasta enero
→ predecir febrero

Entrenar hasta febrero
→ predecir marzo

Entrenar hasta marzo
→ predecir abril

Consideraciones clínicas

NoteAplicación clínica

Una predicción temporal solo es útil si llega con suficiente antelación para modificar una decisión.

Debe definirse:

  • Momento de predicción.
  • Horizonte.
  • Frecuencia de actualización.
  • Latencia.
  • Acción clínica.
  • Coste de falsas alertas.
  • Disponibilidad de datos.
  • Estrategia de monitorización.

Errores frecuentes

  • Hacer split aleatorio.
  • No ordenar por tiempo.
  • Usar información futura.
  • No comparar con naive.
  • Evaluar solo un horizonte.
  • Ignorar irregularidad.
  • Imputar hacia atrás.
  • No usar gap.
  • Mezclar pacientes.
  • Reportar solo RMSE.
  • Ignorar intervalos.
  • No revisar drift.

Flujo recomendado

  1. Definir la serie.
  2. Definir unidad temporal.
  3. Definir momento de predicción.
  4. Definir horizonte.
  5. Explorar tendencia y estacionalidad.
  6. Crear baseline.
  7. Crear features temporales.
  8. Dividir por tiempo.
  9. Aplicar backtesting.
  10. Evaluar por horizonte.
  11. Cuantificar incertidumbre.
  12. Monitorizar drift.
