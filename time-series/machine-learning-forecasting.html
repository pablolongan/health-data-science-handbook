Machine learning para forecasting

TipResumen en 30 segundos

El forecasting con machine learning convierte una serie temporal en un problema supervisado.

Se crean variables como:

  • Lags.
  • Rolling features.
  • Tendencias.
  • Calendario.
  • Variables externas.

Después se entrenan modelos como:

  • Regresión lineal.
  • Random forest.
  • Gradient boosting.
  • XGBoost, LightGBM o CatBoost.

La validación debe respetar el tiempo y compararse siempre con baselines.

De serie temporal a problema supervisado

La idea es transformar:

Serie histórica

en:

Features del pasado
→ target futuro

Ejemplo:

Lag 1
Lag 2
Media de 7 días
Día de la semana
Festivo
Temperatura
        ↓
Modelo
        ↓
Demanda de mañana
NoteIdea clave

El modelo no ve el tiempo directamente: ve features construidas a partir del pasado.

Preparar el dataset

features = [
    "target_lag_1",
    "target_lag_2",
    "target_lag_7",
    "rolling_mean_7",
    "rolling_std_7",
    "day_of_week",
    "is_weekend"
]

target = "target_next_day"

Orden temporal

df = df.sort_values(
    "datetime"
)

Eliminar filas sin target

modeling_df = (
    df[
        [
            "datetime"
        ]
        +
        features
        +
        [
            target
        ]
    ]
    .dropna(
        subset=[
            target
        ]
    )
)

Split temporal

train = modeling_df.loc[
    modeling_df["datetime"]
    <
    "2025-01-01"
]

validation = modeling_df.loc[
    (
        modeling_df["datetime"]
        >=
        "2025-01-01"
    )
    &
    (
        modeling_df["datetime"]
        <
        "2025-07-01"
    )
]

test = modeling_df.loc[
    modeling_df["datetime"]
    >=
    "2025-07-01"
]

Separar X e y

X_train = train[
    features
]

y_train = train[
    target
]

X_validation = validation[
    features
]

y_validation = validation[
    target
]

Baseline naive

naive_prediction = (
    validation[
        "target_lag_1"
    ]
)

Evaluar baseline

from sklearn.metrics import mean_absolute_error
from sklearn.metrics import root_mean_squared_error

naive_mae = mean_absolute_error(
    y_validation,
    naive_prediction
)

naive_rmse = root_mean_squared_error(
    y_validation,
    naive_prediction

Gradient boosting

from sklearn.ensemble import HistGradientBoostingRegressor

gradient_boosting = Pipeline(
    steps=[
        (
            "imputer",
            SimpleImputer(
                strategy="median"
            )
        ),
        (
            "model",
            HistGradientBoostingRegressor(
                learning_rate=0.05,
                max_iter=500,
                max_leaf_nodes=31,
                l2_regularization=1.0,
                random_state=42
            )
        )
    ]
)

Comparar modelos

models = {
    "linear": linear_model,
    "ridge": ridge_model,
    "random_forest": random_forest,
    "gradient_boosting": gradient_boosting
}
import pandas as pd

rows = []

for name, model in models.items():

    model.fit(
        X_train,
        y_train
    )

    prediction = model.predict(
        X_validation
    )

    rows.append(
        {
            "model": name,
            "mae": mean_absolute_error(
                y_validation,
                prediction
            ),
            "rmse": root_mean_squared_error(
                y_validation,
                prediction
            )
        }
    )

comparison_table = pd.DataFrame(
    rows
).sort_values(
    "mae"
)

display(
    comparison_table
)

Forecast one-step

Predice el siguiente paso utilizando valores reales previos.

Historia real
→ predicción t+1

Forecast multi-step

Existen tres estrategias principales:

  • Recursiva.
  • Directa.
  • Multi-output.

Estrategia recursiva

Predice t+1
→ usa esa predicción como lag
→ predice t+2

Ventaja:

  • Un solo modelo.

Limitación:

  • Acumula error.

Estrategia directa

Entrena un modelo por horizonte.

Modelo h1 → t+1
Modelo h2 → t+2
Modelo h3 → t+3

Preparar targets directos

for horizon in [
    1,
    2,
    3,
    7
]:

    modeling_df[
        f"target_h{horizon}"
    ] = (
        modeling_df[
            "target_value"
        ]
        .shift(
            -horizon
        )
    )

Entrenar modelos directos

direct_models = {}

for horizon in [
    1,
    2,
    3,
    7
]:

    target_column = (
        f"target_h{horizon}"
    )

    valid_rows = (
        train[target_column]
        .notna()
    )

    model = HistGradientBoostingRegressor(
        learning_rate=0.05,
        max_iter=300,
        random_state=42
    )

    model.fit(
        train.loc[
            valid_rows,
            features
        ],
        train.loc[
            valid_rows,
            target_column
        ]
    )

    direct_models[
        horizon
    ] = model

Estrategia multi-output

from sklearn.multioutput import MultiOutputRegressor

base_model = RandomForestRegressor(
    n_estimators=500,
    random_state=42,
    n_jobs=-1
)

multi_output_model = MultiOutputRegressor(
    base_model
)

Comparación de estrategias

Estrategia Ventaja Limitación
Recursiva Un solo modelo Acumula error
Directa Menor acumulación Muchos modelos
Multi-output Predice todo junto Mayor complejidad

Ventajas:

  • Más datos.
  • Patrones compartidos.
  • Mejor generalización.

Riesgo temporal de la permutación

Permutar filas aleatoriamente rompe estructura temporal.

Puede ser preferible:

  • Permutar bloques.
  • Hacer ablation studies.
  • Comparar familias de variables.
  • Analizar importancia por periodo.

Ablation study

Modelo 1
→ solo lags

Modelo 2
→ lags + rolling

Modelo 3
→ lags + calendario

Modelo 4
→ todas las features

Drift temporal

Debe monitorizarse:

  • MAE o RMSE por periodo.
  • Sesgo medio.
  • Distribución de lags.
  • Proporción de missing.
  • Cobertura de intervalos.
  • Frecuencia de alertas.

Consideraciones clínicas

NoteAplicación clínica

Machine learning resulta útil cuando existen relaciones no lineales, múltiples variables y muchas series relacionadas.

Debe revisarse:

  • Horizonte.
  • Latencia.
  • Lead time.
  • Pacientes nuevos.
  • Variables externas.
  • Incertidumbre.
  • Drift.
  • Utilidad clínica.

Errores frecuentes

  • No comparar con naive.
  • Usar split aleatorio.
  • Hacer tuning con test.
  • No evaluar por horizonte.
  • Usar exógenas futuras desconocidas.
  • No revisar residuos.
  • No cuantificar incertidumbre.
  • Ignorar pacientes repetidos.
  • No analizar picos.
  • No monitorizar drift.
  • Confundir nowcasting con forecasting.
  • Usar modelos complejos sin baseline.

Flujo recomendado

  1. Definir horizonte.
  2. Construir baseline.
  3. Crear features causales.
  4. Separar temporalmente.
  5. Entrenar modelos lineales.
  6. Probar árboles y boosting.
  7. Aplicar backtesting.
  8. Hacer tuning temporal.
  9. Evaluar por horizonte.
  10. Revisar residuos.
  11. Cuantificar incertidumbre.
  12. Monitorizar drift.
