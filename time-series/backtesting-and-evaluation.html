Backtesting y evaluación temporal

TipResumen en 30 segundos

El backtesting simula cómo habría funcionado un modelo en distintos momentos del pasado.

Una evaluación temporal correcta debe:

  • Respetar el orden cronológico.
  • Comparar con baselines.
  • Evaluar varios horizontes.
  • Revisar estabilidad entre periodos.
  • Analizar intervalos de predicción.
  • Evitar leakage.
  • Reflejar el uso real del modelo.

¿Qué es backtesting?

Backtesting consiste en entrenar el modelo con información pasada y evaluar su rendimiento en periodos posteriores.

NoteIdea clave

El backtesting reproduce repetidamente el escenario real de predecir el futuro.

Por qué no usar split aleatorio

Un split aleatorio mezcla pasado y futuro.

Train
2019, 2023, 2025

Test
2020, 2022, 2024

Esto puede introducir:

  • Información futura.
  • Distribuciones irreales.
  • Leakage.
  • Rendimiento artificialmente alto.

Split temporal simple

train = df.loc[
    df["datetime"]
    <
    "2025-01-01"
]

validation = df.loc[

    &

test = df.loc[
    df["datetime"]
    >=
    "2025-07-01"
]

Ventana expansiva

Cada fold incorpora todo el historial anterior.

Fold 1
Train: [1 2 3]
Test:          [4]

Fold 2
Train: [1 2 3 4]
Test:            [5]

Fold 3
Train: [1 2 3 4 5]
Test:              [6]

Ventajas:

  • Usa toda la información disponible.
  • Adecuada cuando datos antiguos siguen siendo relevantes.

Limitaciones:

  • El train crece continuamente.
  • Puede incluir patrones obsoletos.
  • Mayor coste computacional.

Ventana deslizante

El train mantiene un tamaño fijo.

Fold 1
Train: [1 2 3]
Test:          [4]

Fold 2
Train:   [2 3 4]
Test:            [5]

Fold 3
Train:     [3 4 5]
Test:              [6]

Ventajas:

  • Da más peso a datos recientes.
  • Puede adaptarse mejor a drift.

Limitaciones:

  • Elimina información histórica.
  • Puede reducir tamaño de muestra.

Gap temporal

Un gap separa el final de train del inicio de validation.

Train
────────────

Gap
            ──

Validation
              ──────

Puede ser útil cuando:

  • Hay dependencia temporal fuerte.
  • Las ventanas se solapan.
  • El target utiliza información futura.
  • Existen retrasos de disponibilidad.
  • Se quiere evitar contaminación cercana.

Métricas principales

Las métricas más habituales son:

  • MAE.
  • RMSE.
  • MAPE.
  • sMAPE.
  • WAPE.
  • MASE.
  • Bias.
  • Pinball loss.
  • Cobertura de intervalos.

MAE

\[ MAE = \frac{1}{n} \sum_{t=1}^{n} \left| y_t-\hat{y}_t \right| \]

from sklearn.metrics import mean_absolute_error

mae = mean_absolute_error(
    y_true,
    y_pred
)

Ventajas:

  • Fácil de interpretar.
  • Misma unidad que el target.
  • Menos sensible a outliers que RMSE.

RMSE

\[ RMSE = \sqrt{ \frac{1}{n} \sum_{t=1}^{n} \left( y_t-\hat{y}_t \right)^2 } \]

from sklearn.metrics import root_mean_squared_error

rmse = root_mean_squared_error(
    y_true,
    y_pred
)

Ventajas:

  • Penaliza más los errores grandes.

Limitaciones:

  • Más sensible a outliers.
  • Puede estar dominado por picos.

MAPE

\[ MAPE = \frac{100}{n} \sum_{t=1}^{n} \left| \frac{ y_t-\hat{y}_t }{ y_t } \right| \]

import numpy as np

mape = np.mean(
    np.abs(
        (
            y_true
            -
            y_pred
        )
        /
        y_true
    )
) * 100

Problemas de MAPE

  • No funciona bien con ceros.
  • Es inestable con valores pequeños.
  • Penaliza de forma asimétrica.
  • Puede generar valores enormes.

sMAPE

Una formulación habitual es:

\[ sMAPE = \frac{100}{n} \sum \frac{ 2|y_t-\hat{y}_t| }{ |y_t|+|\hat{y}_t| } \]

smape = (
    100
    *
    np.mean(
        2
        *
        np.abs(
            y_true
            -
            y_pred
        )
        /
        (
            np.abs(
                y_true
            )
            +
            np.abs(
                y_pred
            )
            +
            1e-8
        )
    )
)

WAPE

\[ WAPE = \frac{ \sum |y_t-\hat{y}_t| }{ \sum |y_t| } \]

wape = (
    np.abs(
        y_true
        -
        y_pred
    ).sum()
    /
    np.abs(
        y_true
    ).sum()
)

MASE

MASE compara el error del modelo con un baseline naive.

\[ MASE = \frac{ MAE_{modelo} }{ MAE_{naive} } \]

mase = (
    model_mae
    /
    naive_mae
)

Interpretación:

MASE < 1
→ mejor que naive

MASE = 1
→ igual que naive

MASE > 1
→ peor que naive

Bias

El bias medio mide si el modelo sobrepredice o infrapredice.

\[ Bias = \frac{1}{n} \sum (\hat{y}_t-y_t) \]

bias = np.mean(
    y_pred
    -
    y_true
)
Bias positivo
→ sobrepredicción

Bias negativo
→ infrapredicción

Error porcentual agregado

aggregate_error = (
    y_pred.sum()
    -
    y_true.sum()
)

Puede ser importante en planificación de recursos.

Métricas por horizonte

No debe reportarse solo una métrica global.

horizon_metrics = (
    prediction_df
    .groupby("horizon")
    .apply(
        lambda group:
        pd.Series(
            {
                "mae": mean_absolute_error(
                    group["y_true"],
                    group["y_pred"]
                ),
                "rmse": root_mean_squared_error(
                    group["y_true"],
                    group["y_pred"]
                )
            }
        )
    )
)

Por qué evaluar por horizonte

El rendimiento suele deteriorarse al aumentar el horizonte.

t + 1
→ error bajo

t + 7
→ error mayor

t + 30
→ error aún mayor

Función de coste asimétrica

En algunos problemas, infrapredecir es más costoso que sobrepredecir.

def asymmetric_error(
    y_true,
    y_pred,
    underprediction_weight=3.0
):

    error = (
        y_pred
        -
        y_true
    )

    return np.mean(
        np.where(
            error < 0,
            underprediction_weight
            *
            np.abs(
                error
            ),
            np.abs(
                error
            )
        )
    )

Intervalos demasiado amplios

Un intervalo puede tener buena cobertura simplemente por ser muy ancho.

Por tanto, hay que equilibrar:

  • Cobertura.
  • Anchura.
  • Utilidad.

Pinball loss

Se utiliza para evaluar predicciones cuantílicas.

from sklearn.metrics import mean_pinball_loss

pinball = mean_pinball_loss(
    y_true,
    quantile_prediction,
    alpha=0.90
)

Winkler score

Evalúa intervalos considerando:

  • Anchura.
  • Penalización por observaciones fuera del intervalo.

Calibración temporal

Puede revisarse si:

Intervalo 90 %

También debe evaluarse por:

  • Periodo.
  • Subgrupo.

Primer aviso

Eventos repetidos

Debe definirse:

  • Cuándo empieza un episodio.
  • Cuándo termina.

Evaluación con pacientes repetidos

Las observaciones del mismo paciente no son independientes.

Puede ser necesario:

  • Agrupar métricas por paciente.
  • Separar pacientes.
  • Usar bootstrap por paciente.
  • Reportar variabilidad entre pacientes.

Leakage en backtesting

Ejemplos:

  • Ajustar scaler con todo el dataset.
  • Imputar usando periodos futuros.
  • Seleccionar hiperparámetros con test.
  • Crear lags después de mezclar folds.
  • Calcular rolling features con valores posteriores.
  • Usar una serie revisada retrospectivamente.

Consideraciones clínicas

NoteAplicación clínica

La evaluación debe medir no solo precisión, sino también anticipación, seguridad y carga operativa.

Debe revisarse:

  • Lead time.
  • Falsas alertas.
  • Error en periodos críticos.
  • Error por paciente.
  • Error por centro.
  • Cobertura de intervalos.
  • Impacto operativo.

Errores frecuentes

  • Usar split aleatorio.
  • No comparar con naive.
  • Reportar una sola métrica.
  • No evaluar por horizonte.
  • No evaluar por periodo.
  • Ignorar bias.
  • No revisar picos.
  • Ajustar preprocesamiento fuera del fold.
  • Usar test para tuning.
  • No reproducir latencia real.
  • Ignorar pacientes repetidos.
  • No evaluar intervalos.
  • No monitorizar drift.

Flujo recomendado

  1. Definir escenario real.
  2. Elegir ventana expansiva o deslizante.
  3. Definir gap.
  4. Crear baselines.
  5. Ejecutar walk-forward validation.
  6. Calcular varias métricas.
  7. Evaluar por horizonte.
  8. Evaluar por periodo y subgrupo.
  9. Analizar intervalos.
  10. Revisar bias y picos.
  11. Reservar test final.
  12. Simular producción.
