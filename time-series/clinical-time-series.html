Series temporales clínicas

TipResumen en 30 segundos

Las series temporales clínicas presentan retos específicos:

  • Mediciones irregulares.
  • Múltiples pacientes.
  • Frecuencia de muestreo dependiente del estado clínico.
  • Missingness informativa.
  • Intervenciones que modifican la evolución.
  • Censura y seguimientos incompletos.
  • Necesidad de anticipación clínica útil.

No basta con aplicar técnicas estándar de forecasting sin adaptar el diseño al contexto clínico.

¿Qué es una serie temporal clínica?

Es una secuencia de observaciones relacionadas con la evolución de un paciente.

Ejemplos:

  • Signos vitales.
  • Resultados analíticos.
  • Ecocardiografías.
  • Medicación.
  • Eventos clínicos.
  • Ingresos.
  • Intervenciones.
  • Estados de enfermedad.
Paciente
   ↓
Tiempo
   ↓
Mediciones
Tratamientos
Eventos
Outcomes
NoteIdea clave

En datos clínicos, el proceso de medición también contiene información.

Particularidades de los datos clínicos

Irregularidad

Las observaciones no suelen estar igualmente espaciadas.

Día 0
Día 4
Día 17
Día 63

Múltiples variables

Cada paciente puede tener:

  • Frecuencia cardiaca.
  • Presión arterial.
  • Troponina.
  • NT-proBNP.
  • FEVI.
  • GLS.
  • Tratamientos.
  • Diagnósticos.
  • Eventos.

Múltiples escalas temporales

Minutos
→ monitorización

Horas
→ deterioro agudo

Días
→ ingreso

Meses
→ seguimiento

Años
→ supervivencia

Missingness informativa

Una prueba puede faltar porque:

  • No se consideró necesaria.
  • El paciente estaba estable.
  • No estaba disponible.
  • Hubo pérdida de seguimiento.
  • Se produjo un evento previo.
  • El protocolo cambió.

Intervenciones

Los tratamientos alteran la evolución.

Estado previo
→ intervención
→ respuesta

Por tanto, la serie no es puramente observacional.

Censura

El seguimiento puede terminar antes de observar el evento.

Ejemplos:

  • Fin del estudio.
  • Alta.
  • Traslado.
  • Pérdida de seguimiento.
  • Fallecimiento por otra causa.

Múltiples pacientes

Paciente 1
→ serie 1

Paciente 2
→ serie 2

Paciente 3
→ serie 3

Cada serie puede tener:

  • Longitud distinta.
  • Frecuencia distinta.
  • Variables distintas.
  • Número de eventos distinto.

Unidad de análisis

Debe definirse con precisión.

Puede ser:

  • Paciente.
  • Episodio.
  • Visita.
  • Hora.
  • Día.
  • Ventana.
  • Medición.
  • Evento.

            1,
            1,
            2,
            2

        "datetime": [
            "2026-01-01 08:00",
            "2026-01-01 14:00",

            "2026-01-01 10:00",
            "2026-01-02 10:00"
        ],
        "heart_rate": [
            90,
            96,
            102,
            82,
            84

            0.01,
            None,
            0.03,
            None,

df[

df[

La frecuencia de medición puede ser informativa.

Ventana de observación

Debe definirse cuánto pasado utiliza el modelo.

Ventana de observación
──────────────────────

Momento de predicción
                      │

Horizonte
                      └────────→

Ejemplo:

Usar últimas 24 horas
→ predecir deterioro en próximas 6 horas

Ventana de predicción

Es el periodo futuro en el que se evalúa el outcome.

t
│
├── observación pasada
│
└── evento entre t y t + 6 h

Gap clínico

Puede añadirse un intervalo entre observación y outcome.

Observación
────────────

Gap
            ──

Outcome
              ─────

Esto evita que señales demasiado próximas al evento produzcan una predicción clínicamente inútil.

Ejemplo de target

df[
    "deterioration_next_6h"
] = (
    (
        df[
            "deterioration_datetime"
        ]
        >
        df["datetime"]
    )
    &
    (
        df[
            "deterioration_datetime"
        ]
        <=
        df["datetime"]
        +
        pd.Timedelta(
            hours=6
        )
    )
).astype(int)

Target con gap

gap = pd.Timedelta(
    hours=1
)

horizon = pd.Timedelta(
    hours=6
)
df[
    "deterioration_after_gap"
] = (
    (
        df[
            "deterioration_datetime"
        ]
        >
        df["datetime"]
        +
        gap
    )
    &
    (
        df[
            "deterioration_datetime"
        ]
        <=
        df["datetime"]
        +
        gap
        +
        horizon
    )
).astype(int)

Predicción dinámica

El modelo puede actualizarse repetidamente.

08:00
→ predicción

09:00

10:00
→ nueva predicción

Esto genera múltiples predicciones por paciente.

Dependencia entre observaciones

Las filas del mismo paciente no son independientes.

Esto afecta a:

  • Split.
  • Métricas.
  • Intervalos de confianza.
  • Interpretación.
  • Calibración.

Imputación clínica

Una medición antigua puede dejar de ser válida.

Debe definirse:

  • Tiempo máximo de arrastre.
  • Variable.
  • Contexto clínico.
  • Cambio de estado.
  • Intervenciones intermedias.

Intervenciones como variables

df[
    "treatment_active"
] = (
    (
        df["datetime"]
        >=
        df[
            "treatment_start"
        ]
    )
    &
    (
        df["datetime"]
        <=
        df[
            "treatment_end"
        ]
    )
).astype(int)

Dosis acumulada previa

df[
    "previous_cumulative_dose"
] = (
    df
    .groupby("patient_id")[
        "dose"
    ]
    .cumsum()
    -
    df["dose"]
)

Confounding by indication

Los pacientes más graves reciben más tratamientos.

Por tanto:

Tratamiento
↔ gravedad
↔ outcome

Una asociación predictiva no implica efecto causal.

WarningImportante

Un modelo predictivo no estima automáticamente el efecto de un tratamiento.

Baseline clínico

Puede definirse como:

  • Primera valoración pretratamiento.
  • Valor más cercano al inicio.
  • Media de varias mediciones.
  • Estado adjudicado por expertos.

Cambio desde baseline

df[
    "lvef_change_from_baseline"
] = (
    df["lvef"]
    -
    df[
        "lvef_baseline"
    ]
)

Cambio relativo

df[
    "gls_relative_change"
] = (
    df["gls"]
    -
    df[
        "gls_baseline"
    ]
) / (
    df[
        "gls_baseline"
    ].abs()
)

Eventos recurrentes

Un paciente puede experimentar varios eventos.

Ejemplos:

  • Reingresos.
  • Infecciones.
  • Crisis.
  • Episodios de arritmia.

Debe definirse:

  • Reinicio del riesgo.
  • Dependencia entre eventos.
  • Tiempo desde evento anterior.
  • Evento terminal.

Datos de alta frecuencia

Signos vitales pueden medirse cada segundo o minuto.

Problemas:

  • Gran volumen.
  • Artefactos.
  • Señales repetidas.
  • Alarmas.
  • Dependencia fuerte.

Variables estáticas y dinámicas

Estáticas

Dinámicas

Modelo global

Un modelo global aprende de múltiples pacientes.

Ventajas:

  • Más datos.
  • Patrones compartidos.
  • Aplicación a pacientes nuevos.

Limitaciones:

  • Heterogeneidad.
  • Diferencias entre centros.
  • Riesgo de sesgo.
  • Dependencia entre observaciones.

Embeddings de paciente

Pueden representar características latentes individuales.

Pero pueden memorizar pacientes y reducir generalización.

Evita contar alertas consecutivas como alertas independientes.

Alerta
→ silencio de 6 horas
→ próxima alerta posible

Fatiga de alertas

Debe evaluarse:

  • Alertas por turno.

  • Duración de alertas.
  • Casos revisables.

Calibración

Una probabilidad del 20 % debería corresponder aproximadamente a un 20 % de eventos en casos similares.

Debe evaluarse:

  • Globalmente.
  • Por centro.
  • Por periodo.
  • Por subgrupo.
  • Por horizonte.

Evaluación por paciente

patient_metrics = (
    prediction_df
    .groupby("patient_id")
    .apply(
        evaluate_patient
    )
)

Macro average

Cada paciente pesa igual.

Micro average

Cada predicción pesa igual.

Ambas pueden producir resultados diferentes.

Evaluación por centro

center_metrics = (
    prediction_df
    .groupby("center")
    .apply(

Validación prospectiva

El modelo se ejecuta sobre nuevos pacientes sin modificar decisiones inicialmente.

Puede realizarse en modo:

  • Silencioso.
  • Shadow mode.
  • Observacional.
  • Prospectivo intervencionista.

Shadow mode

El modelo genera predicciones, pero los profesionales no las ven.

Permite evaluar:

  • Rendimiento real.
  • Latencia.
  • Integración.
  • Drift.
  • Volumen de alertas.

Data leakage clínico

Ejemplos:

  • Diagnóstico documentado después del evento.
  • Tratamiento iniciado como respuesta al deterioro.
  • Resultado validado retrospectivamente.
  • Fecha de alta.
  • Duración total del episodio.
  • Código final de facturación.
  • Información del futuro en imputación.

Leakage por documentación

La hora registrada puede no coincidir con la hora real de disponibilidad.

Debe distinguirse:

  • Hora del evento.
  • Hora de solicitud.
  • Hora de toma.
  • Hora de validación.
  • Hora de disponibilidad en sistema.

Latencia

Muestra tomada
→ 10:00

Resultado validado
→ 11:00

Disponible para modelo
→ 11:05

El modelo no puede usarlo a las 10:30.

Tabla de disponibilidad

Variable Hora clínica Hora disponible Uso permitido
Signo vital 10:00 10:01 Sí
Analítica 10:00 11:00 Desde 11:00
Diagnóstico final Día 5 Día 5 No al ingreso
Fecha de alta Día 7 Día 7 No antes

Drift clínico

Puede aparecer por:

  • Nuevo protocolo.
  • Cambio de laboratorio.
  • Nueva población.
  • Cambio de sensor.
  • Cambio de codificación.
  • Nueva indicación terapéutica.

Monitorización

Debe incluir:

  • Disponibilidad de variables.
  • Distribución.
  • Frecuencia de medición.
  • Error.
  • Calibración.
  • Volumen de alertas.
  • Rendimiento por centro.

Sesgo

Debe evaluarse por:

  • Edad.
  • Sexo.
  • Diagnóstico.
  • Centro.
  • Gravedad.
  • Grupo socioeconómico.
  • Disponibilidad de seguimiento.

Fairness temporal

Los subgrupos pueden tener:

  • Distinta frecuencia de medición.
  • Distinta duración de seguimiento.
  • Diferente acceso a pruebas.
  • Diferente prevalencia.

Interpretabilidad clínica

Debe explicar:

  • Qué variables influyen.
  • Qué periodo temporal importa.
  • Qué cambio activó la alerta.
  • Qué incertidumbre existe.
  • Qué acción se espera.

Explicaciones temporales

Ejemplo:

Riesgo elevado por:
- aumento de frecuencia cardiaca en 6 h
- troponina reciente elevada
- descenso de FEVI desde baseline

Riesgo de causalidad aparente

Una feature predictiva puede reflejar una respuesta clínica previa.

Ejemplo:

Mayor monitorización
→ mayor riesgo predicho

Puede indicar que los profesionales ya detectaron deterioro.

Consideraciones éticas

  • Transparencia.
  • Supervisión humana.
  • Gestión de falsos negativos.
  • Gestión de falsas alertas.
  • Privacidad.
  • Validación local.
  • Impacto en workflow.

Flujo recomendado

  1. Definir población.
  2. Definir unidad temporal.
  3. Definir momento de predicción.
  4. Definir ventana de observación.
  5. Definir gap.
  6. Definir horizonte.
  7. Revisar disponibilidad.
  8. Construir features causales.
  9. Separar pacientes y tiempo.
  10. Evaluar alertas y lead time.
  11. Validar externamente.
  12. Monitorizar prospectivamente.

Errores frecuentes

  • Tratar visitas como intervalos regulares.
  • Ignorar missingness informativa.
  • Mezclar pacientes en train y test.
  • Usar información documentada después.
  • No definir gap.
  • Evaluar solo AUROC.
  • No medir lead time.
  • Contar alertas repetidas.
  • Ignorar intervenciones.
  • Interpretar predicción como causalidad.
  • No validar por centro.
  • No simular latencia real.
  • No monitorizar drift.
  • No revisar sesgo.
