Feature engineering temporal

TipResumen en 30 segundos

El feature engineering temporal convierte una serie en variables utilizables por modelos de machine learning.

Las familias principales son:

  • Lags.
  • Diferencias.
  • Estadísticos móviles.
  • Tendencias recientes.
  • Variables de calendario.
  • Tiempo desde eventos.
  • Resúmenes por ventanas.
  • Variables estáticas y dinámicas.

Todas deben construirse usando únicamente información disponible en el momento de predicción.

¿Qué es feature engineering temporal?

Consiste en transformar la historia de una serie en variables explicativas.

NoteIdea clave

El objetivo es resumir el pasado sin introducir información futura.

Preparar los datos

import pandas as pd

df["datetime"] = pd.to_datetime(
    df["datetime"]
)
df = df.sort_values(
    [
        "patient_id",
        "datetime"
    ]
)

Unidad de análisis

Cada fila puede representar:

  • Una hora.
  • Un día.
  • Una visita.
  • Una medición.
  • Una ventana.
  • Un episodio.

La elección afecta a todas las variables posteriores.

Lags

Un lag representa un valor pasado.

df[
    "heart_rate_lag_1"
] = (
    df
    .groupby("patient_id")[
        "heart_rate"
    ]
    .shift(1)
)

Varios lags

for lag in [
    1,
    2,
    3,
    6,
    12
]:

    df[
        f"heart_rate_lag_{lag}"
    ] = (
        df
        .groupby("patient_id")[
            "heart_rate"
        ]
        .shift(lag)
    )

Elegir lags

Los lags pueden basarse en:

  • Conocimiento clínico.
  • Frecuencia de observación.
  • ACF y PACF.
  • Horizonte.
  • Coste computacional.
  • Disponibilidad real.

Tendencia reciente

Puede estimarse mediante una pendiente.

import numpy as np

def slope(
    values
):

    if len(values) < 2:
        return np.nan

    x = np.arange(
        len(values)
    )

    return np.polyfit(
        x,
        values,
        1
    )[0]
df[
    "heart_rate_slope_6"
] = (
    df
    .groupby("patient_id")[
        "heart_rate"
    ]
    .transform(
        lambda series:
        series
        .shift(1)
        .rolling(
            window=6
        )
        .apply(
            slope,
            raw=True
        )
    )
)

Pendiente con tiempo real

En series irregulares, la pendiente debe considerar tiempos reales.

def time_aware_slope(
    values,
    timestamps
):

    if len(values) < 2:
        return np.nan

    hours = (
        timestamps
        -
        timestamps[0]
    ).total_seconds() / 3600

    return np.polyfit(
        hours,
        values,
        1
    )[0]

Función para crear ventanas

def add_rolling_features(
    dataframe,
    group_column,
    value_column,
    windows
):

    result = dataframe.copy()

    for window in windows:

        grouped = result.groupby(
            group_column
        )[
            value_column
        ]

        result[
            f"{value_column}_mean_{window}"
        ] = grouped.transform(
            lambda series:
            series
            .shift(1)
            .rolling(
                window=window
            )
            .mean()
        )

        result[
            f"{value_column}_std_{window}"
        ] = grouped.transform(
            lambda series:
            series
            .shift(1)
            .rolling(
                window=window
            )
            .std()
        )

    return result

Aplicar función

Consideraciones clínicas

NoteAplicación clínica

Las ventanas temporales deben reflejar decisiones clínicas reales y tiempos de respuesta plausibles.

Ejemplos:

  • Últimas 6 horas para deterioro agudo.
  • Últimas 24 horas para evolución diaria.
  • Últimos 7 días para seguimiento ambulatorio.
  • Cambio desde baseline para cardiotoxicidad.

Errores frecuentes

  • Crear lags sin ordenar.
  • No agrupar por paciente.
  • Confundir lag de observación con lag temporal.
  • Incluir el instante actual.
  • Calcular medias con toda la trayectoria.
  • Usar variables futuras.
  • No registrar recencia.
  • Resamplear sin justificar.
  • Crear demasiadas features redundantes.
  • No revisar correlación.
  • No hacer ablation.
  • No documentar disponibilidad.

Flujo recomendado

  1. Definir momento de predicción.
  2. Definir horizonte.
  3. Ordenar por entidad y tiempo.
  4. Crear lags.
  5. Crear ventanas.
  6. Añadir diferencias.
  7. Añadir tendencias.
  8. Añadir calendario.
  9. Añadir tiempo desde eventos.
  10. Revisar leakage.
  11. Comparar familias de features.
  12. Monitorizar drift.
