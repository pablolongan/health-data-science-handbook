Gradient boosting

TipResumen en 30 segundos

Gradient boosting construye árboles de forma secuencial.

Cada nuevo árbol intenta corregir los errores cometidos por el conjunto anterior.

La predicción final es la suma de muchos árboles pequeños:

\[ \hat{y} = f_0(X) + \eta f_1(X) + \eta f_2(X) + \cdots + \eta f_M(X) \]

donde \(\eta\) es el learning rate.

¿Qué es gradient boosting?

Gradient boosting es una familia de métodos ensemble.

A diferencia de random forest, que entrena árboles de forma independiente, gradient boosting los entrena uno detrás de otro.

Modelo inicial
      ↓
Calcula errores
      ↓
Nuevo árbol corrige errores
      ↓
Vuelve a calcular errores
      ↓
Otro árbol corrige errores
      ↓
Predicción final
NoteIdea clave

Random forest reduce varianza combinando árboles independientes.

Gradient boosting reduce error construyendo árboles secuenciales.

Intuición

Supongamos que queremos predecir duración de estancia.

El primer modelo predice la media:

Predicción inicial = 5 días

Después calcula los residuos:

Residuo = valor real - predicción

El siguiente árbol aprende a corregir esos residuos.

El proceso se repite muchas veces.

Modelo aditivo

Gradient boosting construye un modelo de la forma:

\[ F_M(X) = F_0(X) + \sum_{m=1}^{M} \eta h_m(X) \]

donde:

  • \(F_0(X)\) es la predicción inicial.
  • \(h_m(X)\) es el árbol añadido en la iteración \(m\).
  • \(\eta\) es el learning rate.
  • \(M\) es el número de árboles.

Clasificación y regresión

Gradient boosting puede utilizarse para:

Clasificación

  • Evento adverso.
  • Reingreso.
  • Complicación.
  • Diagnóstico.
  • Respuesta al tratamiento.

Regresión

  • Duración de estancia.
  • Coste.
  • Presión arterial.
  • Biomarcadores.
  • Fracción de eyección.

features = [

    "weight",
    "troponin",

y_pred = model.predict(

Número de árboles

n_estimators=300

Más árboles permiten aprender patrones más complejos.

Pero demasiados árboles pueden producir overfitting.

Learning rate

learning_rate=0.05

El learning rate controla cuánto contribuye cada árbol.

Learning rate pequeño
→ aprendizaje más lento
→ más árboles
→ mayor regularización

Learning rate grande
→ aprendizaje más rápido
→ menos árboles
→ mayor riesgo de overfitting
ImportantRelación clave

learning_rate y n_estimators deben ajustarse conjuntamente.

Profundidad de los árboles

En boosting se utilizan normalmente árboles pequeños.

max_depth=3

Árboles pequeños:

  • Reducen overfitting.
  • Aprenden interacciones simples.
  • Funcionan bien de forma secuencial.

Stumps

Un stump es un árbol de profundidad 1.

max_depth=1

Solo contiene una división.

Puede ser útil cuando se desea un modelo muy regularizado.

Muestras mínimas por hoja

min_samples_leaf=10

Ayuda a evitar hojas demasiado pequeñas.

Subsampling

subsample=0.8

Cada árbol se entrena con una fracción aleatoria de train.

Esto se conoce como stochastic gradient boosting.

Puede:

  • Reducir overfitting.
  • Aumentar diversidad.
  • Mejorar generalización.

Hiperparámetros principales

Parámetro Función
n_estimators Número de árboles
learning_rate Contribución de cada árbol
max_depth Complejidad de cada árbol
min_samples_split Mínimo para dividir
min_samples_leaf Mínimo por hoja
subsample Fracción de datos por árbol
max_features Variables candidatas por split
loss Función de pérdida

Función de pérdida

En clasificación binaria se utiliza una pérdida logística.

En regresión puede utilizarse:

model = GradientBoostingRegressor(
    loss="squared_error",
    random_state=42
)

Otras pérdidas permiten mayor robustez ante outliers.

Overfitting

Puede aparecer cuando:

  • Hay demasiados árboles.
  • El learning rate es alto.
  • Los árboles son profundos.
  • Las hojas son pequeñas.
  • El dataset es pequeño.
  • Se ajustan demasiados hiperparámetros.

Revisar train y validation

from sklearn.model_selection import cross_validate

scores = cross_validate(
    estimator=pipeline,
    X=X,
    y=y,
    cv=cv,
    scoring={
        "roc_auc": "roc_auc",
        "average_precision": "average_precision"
    },
    return_train_score=True
)
import pandas as pd

results = pd.DataFrame(
    {
        "train_roc_auc": scores[
            "train_roc_auc"
        ],
        "validation_roc_auc": scores[
            "test_roc_auc"
        ]
    }
)

display(
    results
)

Early stopping

Early stopping detiene el entrenamiento cuando validation deja de mejorar.

model = GradientBoostingClassifier(
    n_estimators=1000,
    learning_rate=0.03,
    validation_fraction=0.20,
    n_iter_no_change=20,
    tol=1e-4,
    random_state=42
)
NoteIdea clave

Early stopping permite indicar un número alto de árboles sin entrenar necesariamente todos.

HistGradientBoosting

Scikit-learn también incluye una implementación basada en histogramas.

from sklearn.ensemble import HistGradientBoostingClassifier

model = HistGradientBoostingClassifier(
    learning_rate=0.05,
    max_iter=300,
    max_leaf_nodes=31,
    random_state=42
)

Ventajas:

  • Más rápido en datasets grandes.
  • Menor consumo de memoria.
  • Puede gestionar valores ausentes de forma nativa.
  • Incluye early stopping.

XGBoost

XGBoost es una implementación optimizada de gradient boosting.

from xgboost import XGBClassifier

model = XGBClassifier(
    n_estimators=500,
    learning_rate=0.05,
    max_depth=3,
    subsample=0.8,
    colsample_bytree=0.8,
    eval_metric="logloss",
    random_state=42
)

Aspectos destacados:

  • Regularización.
  • Subsampling.
  • Paralelización.
  • Manejo eficiente de datos tabulares.
  • Valores ausentes.

XGBoost para regresión

from xgboost import XGBRegressor

model = XGBRegressor(
    n_estimators=500,
    learning_rate=0.05,
    max_depth=3,
    random_state=42
)

Regularización en XGBoost

Parámetros habituales:

  • reg_alpha: regularización L1.
  • reg_lambda: regularización L2.
  • gamma: ganancia mínima para dividir.
  • min_child_weight: tamaño mínimo efectivo de hoja.

LightGBM

LightGBM está diseñado para ser rápido y eficiente.

from lightgbm import LGBMClassifier

model = LGBMClassifier(
    n_estimators=500,
    learning_rate=0.05,
    num_leaves=31,
    random_state=42
)

Características:

  • Crecimiento leaf-wise.
  • Alta velocidad.
  • Eficiencia en datasets grandes.
  • Soporte de variables categóricas.

Riesgo de LightGBM

El crecimiento por hojas puede producir overfitting en datasets pequeños.

Parámetros importantes:

  • num_leaves.
  • max_depth.
  • min_child_samples.
  • feature_fraction.
  • bagging_fraction.

CatBoost

CatBoost está especialmente orientado a variables categóricas.

from catboost import CatBoostClassifier

model = CatBoostClassifier(
    iterations=500,
    learning_rate=0.05,
    depth=6,
    verbose=False,
    random_seed=42
)

Características:

  • Tratamiento nativo de categóricas.
  • Reducción de target leakage en encoding.
  • Buen rendimiento con poco ajuste.
  • Manejo de valores ausentes.

Limitaciones de la importancia por impureza

Puede favorecer:

  • Variables continuas.
  • Variables con alta cardinalidad.
  • Variables correlacionadas.

Bias y varianza

Un boosting poco profundo suele tener:

  • Sesgo moderado.
  • Varianza controlada.
  • Buena capacidad para relaciones complejas.

Pero puede sobreajustar si se aumenta demasiado la complejidad.

Validación temporal

En datos clínicos longitudinales:

Train
→ pacientes o episodios antiguos

Test
→ pacientes o episodios posteriores

Esto evalúa mejor el comportamiento futuro.

Validación externa

Puede realizarse en:

  • Otro hospital.
  • Otro país.
  • Otro periodo.
  • Otra población.
  • Cohorte prospectiva.

Baseline

Gradient boosting debe compararse con:

  • Dummy classifier o regressor.
  • Regresión logística o lineal.
  • Árbol de decisión.
  • Random forest.
  • Regla clínica.

Interpretación clínica

NoteAplicación clínica

Gradient boosting puede ofrecer un gran rendimiento en datos tabulares, pero debe acompañarse de calibración, validación externa e interpretación.

Debe revisarse:

  • Sensibilidad y especificidad.
  • PR AUC en eventos raros.
  • Calibración.
  • Umbral clínico.
  • Rendimiento por subgrupos.
  • Estabilidad entre centros.
  • Drift temporal.
  • Disponibilidad de variables.

Errores frecuentes

  • Elegir demasiados árboles.
  • Usar learning rate alto.
  • No aplicar early stopping.
  • Ajustar hiperparámetros con test.
  • Reportar solo ROC AUC.
  • No revisar calibración.
  • Ignorar desbalance.
  • Confiar solo en feature importance.
  • Interpretar SHAP como causalidad.
  • Mezclar pacientes entre folds.
  • No comparar con modelos simples.
  • Usar un modelo complejo en una muestra muy pequeña.

Flujo recomendado

  1. Definir target y clase positiva.
  2. Crear un baseline.
  3. Separar train y test.
  4. Preparar pipeline.
  5. Entrenar un modelo sencillo.
  6. Ajustar learning rate y árboles.
  7. Limitar profundidad.
  8. Aplicar early stopping.
  9. Validar con cross-validation.
  10. Revisar calibración.
  11. Interpretar con permutation importance o SHAP.
  12. Evaluar una vez en test.
