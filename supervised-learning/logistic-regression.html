Regresión logística

TipResumen en 30 segundos

La regresión logística es un modelo de clasificación que estima probabilidades.

Se utiliza principalmente para problemas binarios:

  • Evento: sí o no.
  • Reingreso: sí o no.
  • Respuesta: sí o no.
  • Complicación: sí o no.

Aunque se llama regresión, su objetivo habitual es clasificar.

¿Qué es la regresión logística?

La regresión logística modela la probabilidad de que una observación pertenezca a la clase positiva.

Ejemplo:

Edad + tratamiento + biomarcadores
                ↓
Probabilidad de cardiotoxicidad

La salida del modelo es una probabilidad entre 0 y 1.

0.08
0.42
0.91
NoteIdea clave

La regresión logística no predice directamente una clase: primero estima una probabilidad.

De la regresión lineal a la logística

Una combinación lineal puede escribirse como:

\[ z = \beta_0 + \beta_1x_1 + \beta_2x_2 + \cdots + \beta_px_p \]

El problema es que \(z\) puede tomar cualquier valor real.

Para convertirlo en probabilidad se utiliza la función sigmoide.

Función sigmoide

\[ \sigma(z) = \frac{1}{1+e^{-z}} \]

La sigmoide transforma cualquier valor real en un valor entre 0 y 1.

z muy negativo  → probabilidad cercana a 0
z = 0           → probabilidad 0.5
z muy positivo  → probabilidad cercana a 1

Probabilidad predicha

\[ P(y=1 \mid X) = \frac{ 1 }{ 1+ e^{ - ( \beta_0 + \beta_1x_1 + \cdots + \beta_px_p ) } } \]

Log-odds

La regresión logística modela linealmente los log-odds.

\[ \log \left( \frac{p}{1-p} \right) = \beta_0 + \beta_1x_1 + \cdots + \beta_px_p \]

donde:

  • \(p\) es la probabilidad del evento.
  • \(\frac{p}{1-p}\) son los odds.
  • El logaritmo de los odds es el logit.

Odds

Los odds se definen como:

\[ \text{odds} = \frac{p}{1-p} \]

Ejemplos:

p = 0.50 → odds = 1
p = 0.80 → odds = 4
p = 0.20 → odds = 0.25

Odds ratio

Para una variable continua:

\[ OR = e^{\beta} \]

Si:

β = 0.40

entonces:

import numpy as np

odds_ratio = np.exp(
    0.40
)

Un odds ratio mayor que 1 indica aumento de odds.

Un odds ratio menor que 1 indica disminución de odds.

WarningImportante

Odds ratio no es lo mismo que riesgo relativo.

features = [

Interpretación de coeficientes

En regresión logística, un coeficiente representa el cambio en log-odds asociado a una unidad de cambio en la variable, manteniendo constantes las demás.

El odds ratio facilita la interpretación.

Ejemplo:

OR = 1.20

Puede interpretarse como un aumento del 20 % en los odds por unidad de incremento, manteniendo constantes las demás variables.

CautionPrecaución

La interpretación depende de la unidad de la variable.

Un incremento de 1 año no equivale a un incremento de 1 ng/L.

Escalado

El escalado suele ser recomendable porque:

  • Facilita regularización.
  • Mejora estabilidad numérica.
  • Ayuda a comparar coeficientes.
  • Puede acelerar la convergencia.

Variables categóricas

from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder

numeric_features = [
    "age",
    "weight",
    "troponin"
]

categorical_features = [
    "sex",
    "center",
    "diagnosis"
]
numeric_transformer = Pipeline(
    steps=[
        (
            "imputer",
            SimpleImputer(
                strategy="median"
            )
        ),
        (
            "scaler",
            StandardScaler()
        )
    ]
)

categorical_transformer = Pipeline(
    steps=[
        (
            "imputer",
            SimpleImputer(
                strategy="most_frequent"
            )
        ),
        (
            "encoder",
            OneHotEncoder(
                handle_unknown="ignore"
            )
        )
    ]
)
preprocessor = ColumnTransformer(
    transformers=[
        (
            "numeric",
            numeric_transformer,
            numeric_features
        ),
        (
            "categorical",
            categorical_transformer,
            categorical_features
        )
    ]
)

Pipeline completo

model = Pipeline(

            )
        )
    ]
)

model.fit(

Umbral de clasificación

Por defecto, muchas implementaciones utilizan 0.50.

threshold = 0.50

y_pred = (
    y_probability >= threshold
).astype(int)

Pero puede elegirse otro umbral.

ImportantRegla práctica

El umbral debe elegirse según el uso clínico y validarse sin utilizar test.

Evaluar varios umbrales

from sklearn.metrics import confusion_matrix

thresholds = [
    0.10,
    0.20,
    0.30,
    0.40,
    0.50,
    0.60,
    0.70
]

rows = []

for threshold in thresholds:

    y_pred_threshold = (
        y_probability >= threshold
    ).astype(int)

    tn, fp, fn, tp = confusion_matrix(
        y_test,
        y_pred_threshold
    ).ravel()

    sensitivity = tp / (
        tp + fn
    )

    specificity = tn / (
        tn + fp
    )

    rows.append(
        {
            "threshold": threshold,
            "sensitivity": sensitivity,
            "specificity": specificity,
            "false_positives": fp,
            "false_negatives": fn
        }
    )

threshold_table = pd.DataFrame(
    rows
)

display(
    threshold_table
)

Regularización L2

Es la opción habitual por defecto.

model = LogisticRegression(
    penalty="l2",
    C=1.0,
    solver="lbfgs",
    max_iter=1000,
    random_state=42
)

L2:

  • Reduce coeficientes.
  • Mejora estabilidad.
  • Conserva normalmente todas las variables.

Regularización L1

model = LogisticRegression(
    penalty="l1",
    C=1.0,
    solver="liblinear",
    max_iter=1000,
    random_state=42
)

L1 puede llevar algunos coeficientes a cero.

Elastic Net

model = LogisticRegression(
    penalty="elasticnet",
    solver="saga",
    l1_ratio=0.5,
    C=1.0,
    max_iter=5000,
    random_state=42
)

Combina L1 y L2.

Parámetro C

En regresión logística:

C pequeño
→ regularización fuerte

C grande
→ regularización débil
WarningError frecuente

C funciona en dirección opuesta a alpha.

Ajustar C

from sklearn.model_selection import GridSearchCV
from sklearn.model_selection import StratifiedKFold

cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

param_grid = {
    "classifier__C": [
        0.001,
        0.01,
        0.1,
        1,
        10,
        100
    ]
}

search = GridSearchCV(
    estimator=model,
    param_grid=param_grid,
    cv=cv,
    scoring="roc_auc",
    n_jobs=-1
)

search.fit(
    X_train,
    y_train

SMOTE

SMOTE debe aplicarse dentro de un pipeline de imbalanced-learn.

from imblearn.pipeline import Pipeline
from imblearn.over_sampling import SMOTE

model = Pipeline(
    steps=[
        (
            "preprocessor",
            preprocessor
        ),
        (
            "smote",
            SMOTE(
                random_state=42
            )
        ),
        (
            "classifier",
            LogisticRegression(
                max_iter=1000,
                random_state=42
            )
        )
    ]
)
WarningImportante

SMOTE debe aplicarse solo sobre train o dentro de los folds.

Multicolinealidad

Puede producir:

  • Coeficientes inestables.
  • Signos inesperados.
  • Odds ratios poco fiables.
  • Alta sensibilidad al split.

La regularización ayuda, pero no elimina la necesidad de revisar variables correlacionadas.

Separación completa

Puede ocurrir cuando una variable separa perfectamente las clases.

Consecuencias:

  • Coeficientes muy grandes.
  • Problemas de convergencia.
  • Estimaciones inestables.

La regularización suele ayudar.

Convergencia

Si aparece una advertencia de convergencia:

  • Aumenta max_iter.
  • Escala variables.
  • Revisa colinealidad.
  • Revisa outliers.
  • Cambia solver.
  • Revisa separación completa.
model = LogisticRegression(
    max_iter=5000,
    random_state=42
)

Consideraciones clínicas

NoteAplicación clínica

La regresión logística suele ser un excelente baseline clínico porque combina interpretabilidad, probabilidades y regularización.

Debe revisarse:

  • Calibración.
  • Umbral.
  • Prevalencia.
  • Coste de FP y FN.
  • Estabilidad por centro.
  • Disponibilidad de predictores.
  • Validez externa.

Errores frecuentes

  • Interpretar odds ratio como riesgo relativo.
  • No escalar con regularización.
  • Elegir el umbral con test.
  • Reportar solo accuracy.
  • No evaluar calibración.
  • Ignorar desbalance.
  • Aplicar SMOTE antes del split.
  • Interpretar coeficientes como causalidad.
  • No revisar convergencia.
  • Comparar coeficientes en escalas distintas.
  • Utilizar variables futuras.
  • No comparar con baseline.

Variante Ventaja Limitación

Flujo recomendado

  1. Definir clase positiva.
  2. Revisar prevalencia.
  3. Separar train y test.
  4. Crear pipeline.
  5. Entrenar baseline.
  6. Entrenar regresión logística.
  7. Ajustar regularización.
  8. Evaluar ROC AUC y PR AUC.
  9. Revisar calibración.
  10. Elegir umbral con validation.
  11. Evaluar una vez en test.
  12. Interpretar odds ratios con cautela.
